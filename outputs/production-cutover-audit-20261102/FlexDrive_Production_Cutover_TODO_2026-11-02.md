## 1. პირველი ნაბიჯი — დომენის გადართვამდე ელფოსტის მარშრუტის გამიჯვნა

### D01 · დადასტურებული · DNS-ის შეცვლამდე

**სად:** Namespace-ის DNS ზონა / ელფოსტის ჰოსტინგის პარამეტრები.

ამჟამად `flexdrive.ge`-ის A ჩანაწერი არის `136.243.25.146`, MX მიუთითებს უშუალოდ `flexdrive.ge`-ზე, ხოლო `mail.flexdrive.ge` არის `flexdrive.ge`-ის CNAME. ამიტომ ვებსაიტის ძირითადი A ჩანაწერის DigitalOcean-ზე გადატანა ელფოსტის მისამართსაც ვებჰოსტინგისკენ მიმართავს.

**გასაკეთებელი:**

- [ ] ავიღოთ მიმდინარე DNS ზონის სრული ასლი და Namespace-ისგან დავადასტუროთ ამ საფოსტო მომსახურების ზუსტი MX, IMAP/SMTP და mail-host ჩანაწერები.
- [ ] ვებდომენის გადართვამდე ელფოსტა დამოუკიდებელ, ჰოსტინგის მიერ დადასტურებულ მისამართზე მივმართოთ. თუ პროვაიდერი `mail.flexdrive.ge`-ს გვთავაზობს, მას საკუთარი შესაბამისი A ჩანაწერი დასჭირდება არსებული root-CNAME-ის ნაცვლად; MX-ის სამიზნეც პროვაიდერის ინსტრუქციით განისაზღვროს.
- [ ] შევინარჩუნოთ Brevo-ს verification TXT, ორივე DKIM CNAME, DMARC და საჭირო საფოსტო ჩანაწერები. SPF-ის `a`/`mx` მექანიზმებიც ხელახლა შევადაროთ შეცვლილ მარშრუტს.
- [ ] გადართვის შემდეგ შევამოწმოთ კომპანიის ელფოსტაზე წერილის მიღება და პასუხის გაგზავნა.

**რატომ:** მხოლოდ ვებსაიტის მიბმამ არ უნდა გათიშოს `support@flexdrive.ge` და სხვა არსებული საფოსტო ყუთები. ზემოთ მოცემული IP არის დაკვირვების შედეგი და არ ცვლის პროვაიდერთან ზუსტი საფოსტო სამიზნის დადასტურებას.

- [ ] რეალურად შევამოწმოთ HTTP→HTTPS და `www`→`https://flexdrive.ge` გადასვლა, ბილიკისა და query-ის შენარჩუნებით, ციკლის გარეშე.

**დამოკიდებულება:** D01 უნდა დასრულდეს ძირითადი DNS ჩანაწერის შეცვლამდე. Nameserver-ების გადატანა აუცილებელი არ არის: ცვლილებები მოქმედ Namespace DNS-შიც შეიძლება შესრულდეს.

**რატომ:** პირველი ცვლადი განსაზღვრავს canonical, sitemap და გაზიარების მისამართებს. ამჟამად გამოქვეყნებული გვერდები დროებით frontend მისამართს იყენებს. API-ის შიდა მისამართის შეცვლა მხოლოდ frontend დომენის მიბმის გამო სავალდებულო არ არის: დროებითი backend მისამართი შეიძლება დარჩეს, თუ მას მოქმედად ვინარჩუნებთ.

- [ ] ცვლილებები build/runtime დონეზე შესაბამის scope-ში შევინახოთ და frontend ხელახლა განვათავსოთ; შემდეგ გამოქვეყნებული HTML-იდან და sitemap-იდან დავადასტუროთ მიღებული მნიშვნელობები.

### D04 · დადასტურებული · Backend გარემოს ცვლილებები

**სად:** DigitalOcean → `flexdrive-prod-back` → Settings. `FRONTEND_BASE_URL`, hosts/origins აპის საერთო გარემოშია; OAuth და BOG მისამართები backend კომპონენტის გარემოშია. ცვლადების შეცვლისას ორივე დონეზე გადავამოწმოთ საბოლოო მოქმედი მნიშვნელობა.

| ცვლადი | სამიზნე / მოქმედება |
| --- | --- |
| `FRONTEND_BASE_URL` | `https://flexdrive.ge` |
| `CORS_ALLOWED_ORIGINS` | საბოლოო frontend origin: `https://flexdrive.ge`; დამატებითი origin მხოლოდ რეალური საჭიროებით |
| `CSRF_TRUSTED_ORIGINS` | საბოლოო frontend origin და პირდაპირი Django admin-ის საბოლოო origin, თუ API დომენს ვიყენებთ |
| `DJANGO_ALLOWED_HOSTS` | თუ ვამატებთ API დომენს, დავამატოთ `api.flexdrive.ge` — პროტოკოლის გარეშე; საჭირო დროებითი host არ წავშალოთ ნაადრევად |

| `FACEBOOK_OAUTH_REDIRECT_URI` | `https://flexdrive.ge/auth/facebook/callback` |

| `BOG_CALLBACK_PUBLIC_URL` | საბოლოო API დომენის არჩევისას: `https://api.flexdrive.ge/api/commerce/payments/bog/callback/` |

ამ ველებში ამჟამად დროებითი frontend/backend მისამართებია. `CORS_ALLOWED_ORIGINS` და `CSRF_TRUSTED_ORIGINS` CSV ფორმატით იკითხება; frontend base URL-იც ნაგულისხმევ origins-ში ემატება. საბოლოო კონფიგურაცია ერთიანად უნდა შემოწმდეს, რათა ძველი override არ გამოგვრჩეს.

**რატომ:** `FRONTEND_BASE_URL` მხოლოდ გვერდის ბმული არ არის: მისგან იგება აქტივაციის, პაროლის აღდგენის, პირობებისა და server-side Meta მოვლენის მისამართებიც. შეცვლის შემდეგ backend-ის მოქმედი deployment უნდა განახლდეს.
