**SEO-ის ერთიანი ატვირთვის მომზადება**

საჭიროა ორივე repository-ის ცვლილებები: `flexdrive-back` და `flexdrive-front`. მომხმარებლის შეთანხმებული გეგმით push თავად მომხმარებელი შეასრულებს, დასრულებული სამუშაოების ერთიანად ატვირთვისას. ამ სესიაში push/deployment არ შესრულებულა.

**ბექი პირველად უნდა მომზადდეს**

Production-ის გაშვებისას აუცილებელია მეორე ეტაპის ორივე მიგრაცია:

| მიგრაცია | რას აკეთებს |
| --- | --- |
| `catalog.0028_product_manual_name` | ამატებს ადმინისტრატორში შეცვლილი დასახელების დაცვის ველს. |
| `catalog.0029_auto_product_seo_titles` | მხოლოდ ზუსტად ცნობილი ძველი იმპორტირებული SEO სათაურები გადაჰყავს ავტომატურ რეჟიმზე; განსხვავებულ ხელით დაწერილ ტექსტებს ინარჩუნებს. |

მიგრაციები ლოკალურად უკვე შესრულებულია. Production-ის მდგომარეობა და კავშირი ამ სესიაში არ წაკითხულა. ამ გარემოში production ბაზის კავშირი არ არის კონფიგურირებული; საჭირო იქნება ზუსტად შეთანხმებული production ბაზის/სერვისის გამოყენება.

Production გარემოსა და ზუსტი მიგრაციის გეგმის შემოწმების შემდეგ catalog-ის მიზნობრივი ბრძანებაა:

```sh
python manage.py migrate catalog 0029_auto_product_seo_titles --plan
python manage.py migrate catalog 0029_auto_product_seo_titles
```

ჯერ მოწმდება გეგმა: მოსალოდნელია `0028` და `0029`, თუ წინა `0027` უკვე გამოყენებულია. მოულოდნელი სხვა მიგრაციები წინასწარ უნდა გადაიხედოს. production ბაზის სარეზერვო ასლისა და ამ ორი მიგრაციის შემოწმება ახალი ბექის ტრაფიკზე გაშვებამდე შესრულდეს.

მესამე/მეოთხე ეტაპს დამატებითი მიგრაცია არ გაუჩნდა. მაგრამ მეოთხე ეტაპს ბექის ახალი category detail API სჭირდება: `GET /catalog/categories/<არსებული-slug>/` უნდა იძლეოდეს 200-ს, უცნობი კი 404-ს. ფრონტი ამ API-ს დაეყრდნობა, ამიტომ ახალი ბექის მზადყოფნის შემდეგ უნდა გააქტიურდეს ახალი ფრონტი.

**ატვირთვის შემდეგ შესამოწმებელი კონკრეტული შედეგები**

1. პროდუქტის საწყის HTML-ში OEM და მანქანასთან შესაბამისობა ჩანს; JSON-LD ბლოკები იკითხება, ფასი/მარაგი და სათაური სწორია.
2. უფოტო პროდუქტს Product JSON-LD-ში საერთო სათადარიგო ფოტო არ უწერია, თუმცა გვერდზე გალერეის სათადარიგო სურათი ჩანს.
3. კატალოგის/ბლოგის შემდეგი გვერდის ბმული აქვს `href`-ს და არჩეულ ფილტრებს ინარჩუნებს.
4. არარსებული პროდუქტი და კატეგორია აბრუნებს 404-ს; API-ის დროებითი ჩავარდნა წარმატებული გვერდის სტატუსით არ სრულდება. პროვაიდერის განზრახ გათიშვა ან production-ზე შეცდომის ხელოვნურად გამოწვევა საჭირო არ არის.
5. სათაურის ფორმატი: სახელი, მარკა/მოდელი, წლები, მხარე და მწარმოებელი; OEM/SKU ავტომატურად არ ემატება. ადგილობრივი მონაცემების დათვლა production-ის შედეგს არ ადასტურებს.

დომენზე, ინდექსაციაზე ან პროვაიდერების პარამეტრებზე მოქმედება ამ ატვირთვის ინსტრუქციაში არ შედის და ცალკე მოთხოვნას საჭიროებს.
