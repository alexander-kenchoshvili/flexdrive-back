## მონაცემების კონტრაქტი

- დაცული `GET /api/business/analytics/?start=YYYY-MM-DD&end=YYYY-MM-DD`.
  არსებული დამოუკიდებელი ბიზნესსესია/ადმინისტრატორის უფლება მოწმდება ქეშამდე
  და Google-თან მოთხოვნამდე; პასუხი `no-store`.
- ორივე თარიღი ან არცერთი. ნაგულისხმევად მიმდინარე თვე თბილისის დღემდე.
  მაქსიმუმ 366 დღე, მომავალი თარიღების გარეშე.
- მუდმივი property `538949234`, სავალდებულო `hostName EXACT flexdrive.ge`.
  ძველი დროებითი დომენები, localhost და `www` არ შედის. კერძო `/business`,
  `/admin` გვერდების მოვლენები დამატებით გამოირიცხება.
- პერიოდის მომხმარებლების მთლიანი რაოდენობა ცალკე Google აგრეგატია;
  დღიური უნიკალური მომხმარებლები არ ჯამდება პერიოდის მაჩვენებლად.
- ვიზიტები, მომხმარებლები, ჩართული ვიზიტები, გვერდების ნახვები; დღიური
  გრაფიკი და ცხრილი; პირველი 20 `sessionSourceMedium` წყარო ვიზიტებით.
- ძებნა მხოლოდ `eventName EXACT search` AND
  `customEvent:search_tracking_version EXACT 2`; `search_outcome` შედეგი და
  `searchTerm`. `eventCount` არის შედეგების ნახვების რაოდენობა და არა უნიკალური
  მომხმარებლები ან მოთხოვნის ყოველი კლავიატურის დაჭერა. პირველი 30 სიტყვა/შედეგი;
  საშუალო `averageCustomEvent:search_result_count` Google-დან მოდის.
- ორი read-only batch მოთხოვნა: ჩვეულებრივი აქტივობა და ცალკე ძებნა.
  ძებნის ახალი ველის დამუშავების პრობლემამ ვიზიტების ანგარიში არ უნდა დამალოს.
  `not_configured`, `unavailable`, `empty`, `partial`, `ready`, `stale` განსხვავდება.
  შეცდომა არასდროს გადაიქცევა გამოგონილ ნულოვან მაჩვენებლებად.
- Google-ის thresholding, sampling და სხვა კატეგორიაში გაერთიანების შენიშვნები
  ინტერფეისში ჩანს. თანხმობის/ბრაუზერის გამო დაფარვა შეიძლება არასრული იყოს.
  GA4 გაყიდვის რიცხვები ფინანსური გადახდების ჩანაცვლებისთვის არ გამოიყენება.

## განახლება

პანელის გახსნა/პერიოდის შეცვლა/განახლება იწვევს დაცულ API მოთხოვნას. ბოლო
წარმატებული პასუხი სერვერზე 5 წუთით ინახება. ამის შემდეგ მომდევნო მოთხოვნა
Google-ს მიმართავს. Cron/ფასიანი კონექტორი/ახალი worker არ არის საჭირო.
Google-ის წყაროს მონაცემების დამუშავებას თავისი დაგვიანება აქვს.

ქეშის გასაღებში შედის property, hostname, credential-ის კონფიგურაციის თითის
ანაბეჭდი და ზუსტი პერიოდი. კონფიგურაციის გარეშე ქეში არ გამოიყენება. ლიმიტი ან
შეფერხება 60-წამიან განმეორების შესვენებას იწვევს. ბოლო წარმატებული snapshot
მაქსიმუმ 24 საათით ინახება და წარუმატებელი განახლებისას გამოკვეთილად `stale`
ნიშნით/ძველი მიღების დროით ჩანს. თანადროული ერთი და იმავე პერიოდის მოთხოვნები
ქეშის დროებითი lock-ით იზღუდება. დეველოპმენტზე LocMem, პროდაქშენზე არსებული
Redis პარამეტრები გამოიყენება. HTTP/ბრაუზერის მუდმივ საცავში კერძო მონაცემები
არ ინახება.

## სერვერული ავტორიზაციის დარჩენილი ნაბიჯი

1. Cloud პროექტ `flexdrive-494109`-ში ჩაირთოს **Google Analytics Data API**.
2. მხოლოდ ახალი reader ანგარიშისთვის შეიქმნას ერთი JSON გასაღები — არა არსებული
   sheets-reader-ისთვის. ამას სჭირდება კონკრეტული დადასტურება შექმნის ღილაკამდე.
3. არჩეული გარემოს ბექენდზე მიეთითოს **ერთი** საიდუმლო წყარო:
   - `BUSINESS_GA4_CREDENTIALS_FILE`: JSON ფაილის აბსოლუტური ადგილობრივი გზა;
     ადგილობრივი გასაღები მხოლოდ იგნორირებულ `secrets/` დირექტორიაში.
   - ან `BUSINESS_GA4_CREDENTIALS_JSON`: სრული JSON, ჰოსტინგის secret env-ში.
   ორივეს ერთდროულად გამოყენება კონფიგურაციის შეცდომაა. არცერთი `NUXT_PUBLIC`
   ცვლადი არ გამოიყენება; მნიშვნელობები არ ჩაიწეროს Git-ში, სკრინში ან ლოგში.
4. OAuth scope მხოლოდ `analytics.readonly`. ანგარიშის email და Google-ის token
   endpoint მოწმდება; customer OAuth/გარემოს სხვა Google credentials არ გამოიყენება.
5. რეალური ავტორიზაციით გადავამოწმოთ ანგარიშის წამოღება. დომენის გადატანამდე
   ნამდვილი ცარიელი პასუხი მოსალოდნელია; მონაცემის არსებობა არ უნდა გამოვიგონოთ.
   დომენის გადატანის/კოდის ატვირთვის შემდეგ ცალკე შევამოწმოთ მოვლენების მიწოდება
   და მოხმარებული ველების თავსებადობა რეალურ Google API-ზე.
