თარიღი: 25 ნოემბერი 2026  
სტატუსი: განხორციელება დაწყებულია მფლობელის მითითებით 25 ნოემბერს 2026

„კრედოს განვადება“. ორივე გამოიყენებს კრედოს ერთ საბანკო გარემოს.
საწყისი გეგმა არის ერთი Shop ID, რომელზეც ბანკს ორივე პროდუქტი გააქტიურებული
ექნება. მომხმარებელი საბოლოო ვადასა და პირობებს კრედოს გვერდზე ირჩევს.

მფლობელმა დაადასტურა გეგმის შესრულების დაწყება. ეს თანხმობა შეეხება კოდის განხორციელებას; გასაღებების შეტანა,
ბაზის მიგრაცია, განთავსება, რეალური განაცხადი და საჯარო ჩართვა შესრულდება
შესაბამის ეტაპზე შეთანხმებული მოცულობით. ამ დოკუმენტის მომზადება მათ არ იწყებს.

## უკვე ცნობილი პირობები

ქვემოთ კომერციული და საოპერაციო პირობები ეყრდნობა მფლობელის მიერ გადმოცემულ
ბანკის წარმომადგენლის პასუხებს 2026 წლის 25 ნოემბრის მდგომარეობით.

- საიტზე „დაყავი“ და სტანდარტული განვადება ცალკე უნდა გამოჩნდეს.
- „დაყავი“ წარმომადგენელმა აღწერა 3–4 თვის 0%-იანი პირობებით;
  უფრო გრძელ ვადაზე მოქმედებს სტანდარტული პროცენტიანი განვადება.
  მომხმარებლისთვის საბოლოო ტექსტი შეთანხმდება ბანკის ოფიციალურ პირობებთან.
- ორივე შემთხვევაში ბანკი მერჩანტს 3%-ს აკლებს. საკომისიოს ზუსტი საფუძველი,
  დამრგვალება და დაბრუნებისას მისი ბედი ჯერ დასაზუსტებელია.
- მომხმარებელი კრედოს გვერდზე ხელს აწერს ხელშეკრულებასა და გრაფიკს.
- ხელმოწერის შემდეგ მერჩანტი აგზავნის ნივთს და კრედოს კაბინეტში ხელით
  ნიშნავს „გაგზავნილია“-ს. მომხმარებელს მისდის შეტყობინება მიღების დასადასტურებლად.
- თანხის ჩარიცხვა მიბმულია პროცესის დასრულებაზე. თუ მომხმარებელი მიღებას
  სისტემაში არ ადასტურებს, წარმომადგენლის განმარტებით მერჩანტი უკავშირდება ბანკს;
  ბანკი ჩაბარებას აზუსტებს და პროცესს ხელით ასრულებს. ამ გზით დასრულების შემდეგ
  წარმომადგენელმა დაასახელა იმავე ან მომდევნო დღეს ჩარიცხვა.
- ცალკე სატესტო გარემო ბანკს არ აქვს. წარმომადგენელმა დაუშვა რეალურ გარემოში
  ტესტირება და ბანკის მხრიდან განვადების გაუქმება; კონკრეტული ტესტი ჯერ შეთანხმებული არ არის.
- ამჟამად ორივე არჩევანი ბანკის გვერდს ერთ საწყის ვადაზე გახსნის.
  ღილაკის მიხედვით განსხვავებული საწყისი ვადის ფუნქცია წარმომადგენლის თქმით
  15 დეკემბრისთვის იგეგმება. ეს არ არის უკვე ხელმისაწვდომი API შესაძლებლობა
  და მისი ავტომატური ამუშავება ჩვენს კოდში წინასწარ არ იგულისხმება.

ოფიციალური API აღწერს კალათის გაგზავნას, ბანკის ბმულზე გადამისამართებასა და
სტატუსის გამოთხოვას. ფასები გადაიცემა თეთრებში; რამდენიმე პროდუქტის გაგზავნა
შესაძლებელია. პროდუქტის `type` სქემაში მუდმივად `0`-ია და არ გამოიყენება
„დაყავის“ ასარჩევად. [განაცხადის შექმნის დოკუმენტაცია](https://4developers.credo.ge/apidoc/docs-site/6000022/request-installment-3472458e0)

## მომხმარებლისა და მფლობელის გზა

მომხმარებელი კალათიდან ან „ახლავე ყიდვით“ გადადის არსებულ ჩექაუთში, ავსებს
მყიდველისა და მიტანის მონაცემებს და ირჩევს კრედოს ერთ-ერთ შეთავაზებას.
საიტი ამოწმებს ფასსა და მარაგს, ინახავს შეძენის მონაცემებს და ქმნის განაცხადს.
შემდეგ მომხმარებელი კრედოს გვერდზე ირჩევს საბოლოო პირობებს და გადის ბანკის პროცესს.

ჩვენი სერვერი განაცხადის მდგომარეობას ბანკისგან პერიოდულად ითხოვს.
განხილვის, უარისა და ხელმოწერის მოლოდინი საიტზე განსხვავებული ტექსტებით აისახება.
ბანკიდან საიტზე ავტომატური დაბრუნების შესაძლებლობა დასაზუსტებელია;
მოქმედი განაცხადის ნახვა და გაგრძელება ავტომატურ დაბრუნებაზე დამოკიდებული არ იქნება.

მფლობელი ხედავს ხელმოწერილ, გასაგზავნად მზად შეკვეთას. ნივთის რეალური გაგზავნის
შემდეგ კრედოს კაბინეტშიც ნიშნავს გაგზავნას. კურიერისა და კრედოს სტატუსები
ერთმანეთს ავტომატურად არ ჩაანაცვლებს. ჩაბარების შემდეგ კონტროლდება ბანკში
დასრულება და ანგარიშსწორება; დაუდასტურებელ მიღებაზე საჭიროა ბანკთან დაკავშირება.
